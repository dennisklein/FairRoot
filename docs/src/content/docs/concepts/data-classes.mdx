Each data level of an event has its own class: MC points, digis, hits and track parameters. FairRoot gives a base class with the common members for each level, and most of them can hold links to the source objects. Your classes derive from them and need a ROOT dictionary, so that the runs can write and read them.

## Data levels and base classes

| Level | Made by | Base class | Members of the base class |
| --- | --- | --- | --- |
| MC point | A detector, during the transport | [`FairMCPoint`](/api/FairMCPoint/) | Track ID, event ID, detector ID, position, momentum, time, track length, energy loss |
| Digi | A digitization task | [`FairTimeStamp`](/api/FairTimeStamp/) | Time stamp and its error |
| Hit | A reconstruction task | [`FairHit`](/api/FairHit/) | The time stamp, a detector ID, the position and its errors, a reference index |
| Track parameters | A track fit | [`FairTrackParam`](/api/FairTrackParam/) | x, y, z, tx, ty, q/p and a covariance matrix |

The MC tracks come from the stack: see [The particle stack and MC tracks](/simulation/stack/). The event header has its own page: [Event headers and run IDs](/concepts/event-headers/).

The base classes form this tree. Each header names the base class in the class line, for example [FairHit.h](/source/fairroot/base/event/FairHit.h/#L22).

```text
TObject
├── FairMultiLinkedData_Interface   optional links
│   ├── FairMCPoint                 MC point
│   └── FairTimeStamp               time stamp
│       └── FairHit                 hit
└── FairTrackParam                  track parameters
```

[`FairMultiLinkedData_Interface`](/api/FairMultiLinkedData_Interface/) holds a pointer to a set of links, not the links. It makes the set at the first change, and only when links are on ([FairMultiLinkedData_Interface.cxx](/source/fairroot/base/event/FairMultiLinkedData_Interface.cxx/#L64-L75)). Without links, the pointer stays empty. See [Links between data levels](/concepts/links/).

## MC points

A detector makes MC points in `ProcessHits()`, while the transport engine moves a track through a sensitive volume. See [Write a detector](/simulation/detectors/). Derive your point class from `FairMCPoint`, which has these members:

<Snippet file="fairroot/base/event/FairMCPoint.h" start="  protected:" end="ClassDefOverride(FairMCPoint, 5);" title="FairMCPoint.h" />

The comments give the units: cm, GeV and ns. The constructor takes the track ID, the detector ID, the position, the momentum, the time, the track length and the energy loss. A last argument, the event ID, is 0 by default ([FairMCPoint.h](/source/fairroot/base/event/FairMCPoint.h/#L37-L44)). The default constructor sets the track ID and the detector ID to -1, and all other members to 0 ([FairMCPoint.cxx](/source/fairroot/base/event/FairMCPoint.cxx/#L12-L26)).

During the transport, the track ID is the index of the particle in the stack. At the end of the event, `FairMCApplication::FinishEvent()` calls `UpdateTrackIndex()` of the stack ([FairMCApplication.cxx](/source/fairroot/base/sim/FairMCApplication.cxx/#L645-L648)). `FairStack` of the examples then writes the index of the stored MC track into each MC point:

<Snippet file="examples/common/mcstack/FairStack.cxx" start="while ((hitArray = det->GetCollection(iColl++)))" end="// Collections of this detector" title="examples/common/mcstack/FairStack.cxx" />

The stack gets the points from [`FairDetector::GetCollection()`](/api/FairDetector/#GetCollection), which returns a `TClonesArray`. With links on, `SetLink()` also gives each MC point a link to its MC track. The stack does not correct points in other containers. See [The particle stack and MC tracks](/simulation/stack/).

## Digis and time stamps

[`FairTimeStamp`](/api/FairTimeStamp/) adds a time stamp and its error, both `Double_t`. Both start at -1, and the member comment gives the unit ns ([FairTimeStamp.h](/source/fairroot/base/event/FairTimeStamp.h/#L79-L81)). A digi class derives from `FairTimeStamp` and adds the channel. The digi of the serialization example gives the time to the base class:

<Snippet file="examples/MQ/serialization/data/MyDigi.h" start="class MyDigi : public FairTimeStamp" end="~MyDigi() override = default;" title="examples/MQ/serialization/data/MyDigi.h" />

`FairTimeStamp` has three functions for time-based processing:

| Function | What it does | Used by |
| --- | --- | --- |
| [`Compare()`](/api/FairTimeStamp/#Compare) | Orders by time stamp, then by its error. [`IsSortable()`](/api/FairTimeStamp/#IsSortable) returns true. | `TClonesArray::Sort()`, for example in [FairTestDetectorTimeRecoTask.cxx](/source/examples/advanced/Tutorial3/timeBasedSimulation/FairTestDetectorTimeRecoTask.cxx/#L94) |
| [`equal()`](/api/FairTimeStamp/#equal) | Returns true for the same time stamp and the same error. | [`FairWriteoutBuffer`](/api/FairWriteoutBuffer/), to find an older digi of the same channel ([FairWriteoutBuffer.cxx](/source/fairroot/base/steer/FairWriteoutBuffer.cxx/#L184)) |
| [`operator<`](/api/FairTimeStamp/#operator-lt) | Compares the time stamps only. | Your code |

## Hits

[`FairHit`](/api/FairHit/) derives from `FairTimeStamp`. It adds a detector ID, the position, the position errors and a reference index:

<Snippet file="fairroot/base/event/FairHit.h" start="  protected:" end="ClassDefOverride(FairHit, 3);" title="FairHit.h" />

The constructor [`FairHit(detID, pos, dpos, index)`](/api/FairHit/#FairHit-2) sets all of them. The time stamp stays at -1, so set it with `SetTimeStamp()` ([FairHit.cxx](/source/fairroot/base/event/FairHit.cxx/#L22-L32)).

The FairRoot libraries do not interpret the reference index. Use it for a one-to-one relation, for example from a hit to its MC point. The hit producer of Tutorial 4 stores the index of the MC point ([FairTutorialDet4HitProducerIdealMisalign.cxx](/source/examples/simulation/Tutorial4/src/reco/FairTutorialDet4HitProducerIdealMisalign.cxx/#L174)). Its plot macro uses the index to get the point back ([plots.C](/source/examples/simulation/Tutorial4/macros/plots.C/#L118-L121)). For more than one source object, use links.

## Track parameters

[`FairTrackParam`](/api/FairTrackParam/) holds the result of a track fit at one z position: x, y, the slopes tx = dx/dz and ty = dy/dz, and q/p. The z coordinate tells where the parameters are, and it is not a fit parameter. An array keeps the 15 elements of the upper triangle of the 5×5 covariance matrix:

<Snippet file="fairroot/base/event/FairTrackParam.h" start="  private:" end="ClassDefOverride(FairTrackParam, 1);" title="FairTrackParam.h" />

`FairTrackParam` derives from `TObject` directly, so it has no time stamp and no links. [`Momentum()`](/api/FairTrackParam/#Momentum) calculates the momentum from tx, ty and q/p. It always gives a positive pz, and it uses p = 10⁴ GeV when |q/p| is 10⁻⁴ or less ([FairTrackParam.cxx](/source/fairroot/base/event/FairTrackParam.cxx/#L82-L89)). See [Track parameters and propagation](/reconstruction/tracks/).

## Write a data class

<Steps>

1. Derive the class from the base class of its level: `FairMCPoint`, `FairTimeStamp` or `FairHit`.

2. Give the class a default constructor. ROOT calls it when it reads an object from a file.

3. Use `Double32_t` for the members that do not need full precision in the file. ROOT writes them as 32-bit floats.

4. Start the comment of a member with `//!` if the member must not go into the file.

5. Add `ClassDefOverride(MyClass, 1)` at the end of the class.

6. Add the class to the LinkDef file of your library, with a `+` after the name.

7. Register a container of the class as a branch. See [Containers](#containers).

</Steps>

### Dictionary macros

| Macro | Example in FairRoot | Use it for |
| --- | --- | --- |
| `ClassDefOverride(Name, version)` | `FairMCPoint`, `FairHit`, `FairTimeStamp` | A class that derives from a class with a dictionary macro, for example from `TObject` |
| `ClassDef(Name, version)` | `NewDetectorPoint` of the templates | The same, without `override` on the functions that the macro declares |
| `ClassDefNV(Name, version)` | [`FairLink`](/source/fairroot/base/event/FairLink.h/#L110), `CustomClass` of Tutorial 2 | A class without virtual functions: the macro adds none |

The version tells ROOT the layout of the class in the file. Increase it each time that you add, remove or change a data member. ROOT stores the version with the data and uses it to read files that an older layout wrote (schema evolution).

A comment that starts with `//!` makes a member transient: ROOT does not write it. `FairMultiLinkedData` keeps its flags out of the file in this way:

## Containers

A branch holds the objects of one level for one event. Most FairRoot code uses a `TClonesArray`. With `RegisterAny()`, a branch can also be a `std::vector` or any other type with a dictionary.

| | `TClonesArray` | `std::vector<T>` |
| --- | --- | --- |
| Register the branch | [`Register()`](/api/FairRootManager/#Register-2) | [`RegisterAny()`](/api/FairRootManager/#RegisterAny) |
| Read it in a task | [`GetObject()`](/api/FairRootManager/#GetObject) and a cast | [`InitObjectAs<T const*>()`](/api/FairRootManager/#InitObjectAs) |
| Element class | Derives from `TObject` | Any class with a dictionary |
| Link history through its elements | Yes | No: the link code gets the branch with `GetObject()`, which does not find `RegisterAny()` branches ([FairRootManager.cxx](/source/fairroot/base/steer/FairRootManager.cxx/#L723-L753)) |
| `FairStack` corrects the track IDs of its MC points | Yes, through `GetCollection()` | No |
| `FairPrintFairLinks` and the datamatch library read it | Yes | No |

A `TClonesArray` keeps its memory from event to event. Tutorial 3 makes the array of digis in `Init()` and registers it:

<Snippet file="examples/advanced/Tutorial3/digitization/FairTestDetectorDigiTask.cxx" start="// Create and register output array" end="ioman->Register(" title="FairTestDetectorDigiTask.cxx" />

In `Exec()`, the task empties the array with `Delete()` ([FairTestDetectorDigiTask.cxx](/source/examples/advanced/Tutorial3/digitization/FairTestDetectorDigiTask.cxx/#L56)). Then it makes each digi in place with `new ((*fDigiArray)[ipnt])` ([FairTestDetectorDigiTask.cxx](/source/examples/advanced/Tutorial3/digitization/FairTestDetectorDigiTask.cxx/#L72)).

:::caution[Links need Delete()]
With links on, each object owns a set of links on the heap. `TClonesArray::Delete()` calls the destructors and frees the sets. `TClonesArray::Clear()` does not call the destructors, so the sets of the old objects stay in memory.
:::

:::

## Serialization for FairMQ

For FairMQ devices, the library `FairRoot::BaseMQ` gives Boost serialization for `FairTimeStamp`, `FairHit` and `FairMCPoint` in support headers. Include the support header of your base class, for example `FairTimeStampBoostSerializationSupport.h`. Then give your class a `serialize()` function that writes the base class with `base_object`, and then its own members:

<Snippet file="examples/MQ/serialization/data/MyDigi.h" start="template<class Archive>" title="MyDigi.h" />

The support headers do not write the links. An object that crosses a channel in this way arrives without links ([FairTimeStampBoostSerializationSupport.h](/source/fairroot/basemq/FairTimeStampBoostSerializationSupport.h/#L18-L30)). See [Serialize FairRoot data for messages](/online/serialization/).

:::caution[Energy loss of FairMCPoint]
When it reads a point, the support header for `FairMCPoint` gives the energy loss to `SetLength()`, not to `SetEnergyLoss()` ([FairMCPointBoostSerializationSupport.h](/source/fairroot/basemq/FairMCPointBoostSerializationSupport.h/#L51-L57)).
:::
