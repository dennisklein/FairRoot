A deprecated API still works, but a later release of FairRoot removes it. FairRoot marks these APIs
in the code, so that the compiler warns you when your code uses them. This page lists each
deprecated item, the release that deprecated it, the planned removal and the replacement.

The data comes from the deprecation marks in the code and from the changelog. When neither gives a
release or a replacement, the tables say "Not stated". For the steps to update a project, see
[Migrate to a new release](/project/migration/).

## How FairRoot marks deprecated code

FairRoot uses four marks:

| Mark | Where | What you see |
| --- | --- | --- |
| The C++ attribute `[[deprecated]]` or `__attribute__((deprecated))` | Functions and data members | A compiler warning at each use, with the message of the attribute |
| A `\deprecated` comment | Above the declaration | Often the release that deprecated the item and the planned removal, else the replacement |
| `#warning` | The headers of the DataMatch library | A compiler warning in each source file that includes one of the headers |
| A build option with the default `OFF` | `CMakeLists.txt` | The classes are not in the libraries until you set the option to `ON` |

A function that has a replacement often has both forms side by side in the header. The
deprecated form gives the name of the replacement in its message:

<Snippet file="fairroot/base/steer/FairRun.h" start="void SetEventHeader(std::unique_ptr" end="FairEventHeader* EvHeader);" />

Some deprecated functions also write a warning to the log when they run, for example the output-file
functions of [`FairRun`](/api/FairRun/) ([FairRun.cxx](/source/fairroot/base/steer/FairRun.cxx/#L201-L230)).
In 18.8.0, FairRoot marked the items that older releases had deprecated with C++14 deprecation
attributes. The changelog of 18.8.0 schedules these items for removal in v20.

### Find the deprecated calls in your code

GCC and Clang report a use of a deprecated function or member with the warning
`-Wdeprecated-declarations`. Build your project and look for this warning in the build log. To stop
the build at each use, add the compiler option `-Werror=deprecated-declarations` to your targets.

FairRoot itself still calls some deprecated functions, so that old user code keeps working. It turns
the warning off around these calls:

<Snippet file="fairroot/base/sim/FairModule.cxx" start="Bool_t FairModule::IsSensitive(const std::string& name)" />

:::note
If you need a deprecated API that has no replacement, tell the FairRoot developers before the
removal. See [Contributing](/project/contributing/).
:::

## Build options and libraries

FairRoot 19.0.0 builds three deprecated components only on request. The DataMatch library is always
built, but its headers give a warning.

| Component | Deprecated in | Removal | How to get it, replacement |
| --- | --- | --- | --- |
| MbsAPI library, and the MBS and LMD classes of the Online library: [`FairLmdSource`](/api/FairLmdSource/), [`FairMbsSource`](/api/FairMbsSource/), [`FairMbsStreamSource`](/api/FairMbsStreamSource/), [`FairRemoteSource`](/api/FairRemoteSource/), [`MRevBuffer`](/api/MRevBuffer/) | 18.8.0 | Planned for 20, "the next major release" | Off by default since 19.0.0. Set `-DBUILD_MBS=ON`. No replacement. |
| PROOF support: [`FairRunAnaProof`](/api/FairRunAnaProof/), [`FairAnaSelector`](/api/FairAnaSelector/) | 19.0.0 | Not stated | Off by default. Set `-DBUILD_PROOF_SUPPORT=ON`. ROOT deprecated PROOF in 6.26. No replacement. |
| [`FairEventBuilder`](/api/FairEventBuilder/), [`FairEventBuilderManager`](/api/FairEventBuilderManager/) | 19.0.0 | Not stated | Off by default. Set `-DBUILD_EVENT_BUILDER=ON`. No replacement. |
| DataMatch library (`FairRoot::DataMatch`): [`FairMCMatch`](/api/FairMCMatch/), [`FairMCDataCrawler`](/api/FairMCDataCrawler/), [`FairMCEntry`](/api/FairMCEntry/), [`FairMCList`](/api/FairMCList/), [`FairMCMatchCreatorTask`](/api/FairMCMatchCreatorTask/), [`FairMCMatchLoaderTask`](/api/FairMCMatchLoaderTask/), [`FairMCMatchSelectorTask`](/api/FairMCMatchSelectorTask/), [`FairMCObject`](/api/FairMCObject/), [`FairMCResult`](/api/FairMCResult/), [`FairMCStage`](/api/FairMCStage/) | 18.8.0 | "A future major release" | Always built. No replacement. |

The options are in the top-level [`CMakeLists.txt`](/repo/CMakeLists.txt#L122-L129). Some facts
about them:

- `BUILD_MBS=ON` also sets `BUILD_ONLINE=ON`. The MBS sources are part of the `FairRoot::Online`
  library ([fairroot/online/CMakeLists.txt](/repo/fairroot/online/CMakeLists.txt#L18-L29)).
- The examples [MBS tutorial](/examples/mbs-tutorial/) and [MQ: LMD sampler and unpacker](/examples/mq-lmd/)
  are built only with `BUILD_MBS=ON` ([examples/CMakeLists.txt](/repo/examples/CMakeLists.txt#L39-L54)).
- CMake stops with an error if you set `BUILD_PROOF_SUPPORT=ON` with ROOT 6.32 or later, because
  ROOT 6.32 has no PROOF ([CMakeLists.txt](/repo/CMakeLists.txt#L151-L153)).
- [`FairRunAna::RunEventReco()`](/api/FairRunAna/#RunEventReco) is deprecated "along with
  FairEventBuilder", but FairRoot always builds it.

Each header of the DataMatch library has this block:

<Snippet file="fairroot/datamatch/FairMCMatch.h" start="#ifndef FAIR_SILENCE_DATAMATCH_DEPRECATION" end="#endif" />

To silence the warning, define `FAIR_SILENCE_DATAMATCH_DEPRECATION` for your target. FairRoot does
this for its own build of the library
([fairroot/datamatch/CMakeLists.txt](/repo/fairroot/datamatch/CMakeLists.txt#L42-L44)).

The deprecated functions `SetOutputFile()` and `SetOutputFileName()` still make a `FairRootFileSink`
and give it to the run. Each deprecated output-file function writes a warning to the log
([FairRun.cxx](/source/fairroot/base/steer/FairRun.cxx/#L201-L230)). `SetOutputFileName()` opens the
file at once, although its comment says that it does not make the file
([FairRootFileSink.cxx](/source/fairroot/base/sink/FairRootFileSink.cxx/#L60-L69)).

[`FairRootManager::GetOutFile()`](/api/FairRootManager/#GetOutFile) and
[`GetOutTree()`](/api/FairRootManager/#GetOutTree) are not deprecated. They were deprecated from
18.0.0 to 18.8.0.

### Configuration macros of the transport engine

[`FairGenericVMCConfig`](/api/FairGenericVMCConfig/) configures the transport engine with the ROOT
macros in `CONFIG_DIR`. It has no deprecation mark, but its
[`Setup()`](/api/FairGenericVMCConfig/#Setup) and
[`SetupPostInit()`](/api/FairGenericVMCConfig/#SetupPostInit) write warnings to the log. The
warnings say that the use of the macros is deprecated and point to the YAML implementation in
[examples/common/gconfig](/repo/examples/common/gconfig/):

<Snippet file="fairroot/base/sim/FairGenericVMCConfig.cxx" start="void FairGenericVMCConfig::Setup(const char* mcEngine)" end="Check FairRoot/examples/common/gconfig/" />

[`FairRunSim`](/api/FairRunSim/) uses `FairGenericVMCConfig` when you set no configuration. The
YAML implementation is a class derived from [`FairYamlVMCConfig`](/api/FairYamlVMCConfig/), for
example [`FairVMCConfig`](/source/examples/common/gconfig/FairVMCConfig.h/) of the examples. The code
gives no release for the removal. See [Transport engines and their configuration](/simulation/engines/).

## Logging

Parts of the old interface of [`FairLogger`](/api/FairLogger/) are deprecated. The code gives no
release for the deprecation or for the removal
([FairLogger.h](/source/fairroot/tools/FairLogger.h/#L89-L116)).

| Deprecated API | Replacement |
| --- | --- |
| `FairLogger::Fatal()`, `Error()`, `Warning()`, `Info()`, `Debug()`, `Debug1()` to `Debug4()` | The macro `LOG`, for example `LOG(info) << content;` |
| `FairLogger::IsLogNeeded(FairLogLevel)` | `IsLogNeeded(fair::Severity)`, or `fair::Logger::Logging()` with a severity or a severity string |
| `FairLogger::endl`, `FairLogger::flush` | Nothing. The `LOG` macro adds the line break and flushes the data. |

The enum `FairLogLevel` and the array `LogLevelString` have no deprecation mark. A comment says that
they exist only for older `FairLogger` calls and that they will be deleted
([FairLogger.h](/source/fairroot/tools/FairLogger.h/#L26-L42)). See [Logging](/tools/logging/).
