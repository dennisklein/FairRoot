FairRoot builds up to 16 shared libraries and two header-only libraries. Each library is a CMake
target in the namespace `FairRoot::`, and the build installs all public headers into one
directory. This page lists the libraries and shows how to include the headers and link the
targets.

## Overview

The directory `fairroot/` has one subdirectory for each library
([fairroot/CMakeLists.txt](/repo/fairroot/CMakeLists.txt#L12-L54)):

| --- | --- | --- | --- |
| [`FairRoot::Tools`](#fairroottools) | [fairroot/tools](/repo/fairroot/tools/) | `libFairTools` | always |
| [`FairRoot::Alignment`](#fairrootalignment) | [fairroot/alignment](/repo/fairroot/alignment/) | `libAlignment` | always |
| [`FairRoot::GeoBase`](#fairrootgeobase) | [fairroot/geobase](/repo/fairroot/geobase/) | `libGeoBase` | always |
| [`FairRoot::ParBase`](#fairrootparbase) | [fairroot/parbase](/repo/fairroot/parbase/) | `libParBase` | always |

Some file names are different from the target names, for example `libGen` for
`FairRoot::Generators`. CMake sets this name with the property `OUTPUT_NAME`, for example in
[fairroot/generators/CMakeLists.txt](/repo/fairroot/generators/CMakeLists.txt#L27-L28). The file
also has the platform suffix, for example `.so` on Linux. The build sets the target property
`VERSION` to the FairRoot version, so on Linux `libGen.so` is a link to `libGen.so.19.0.0`
([CMakeLists.txt](/repo/CMakeLists.txt#L250-L252)).

## Build options

These options of the top-level [CMakeLists.txt](/repo/CMakeLists.txt#L120-L131) select
libraries and parts of libraries:

| Option | Default | Effect |
| --- | --- | --- |
| `BUILD_ONLINE` | `ON` | Builds `FairRoot::Online`. |
| `BUILD_MBS` | `OFF` | Builds `FairRoot::MbsAPI` and the MBS sources in `FairRoot::Online`. It also sets `BUILD_ONLINE` to `ON`. |
| `BUILD_BASEMQ` | `ON` | Builds `FairRoot::FairMQ`, `FairRoot::BaseMQ` and `FairRoot::ParMQ`. CMake then requires FairMQ 1.4.0 or newer and Boost 1.67 or newer ([CMakeLists.txt](/repo/CMakeLists.txt#L202-L241)). |
| `BUILD_PROOF_SUPPORT` | `OFF` | Adds `FairRunAnaProof` and `FairAnaSelector` to `FairRoot::Base`. With ROOT 6.32 or newer, CMake stops with an error. |
| `BUILD_EVENT_BUILDER` | `OFF` | Adds `FairEventBuilder` and `FairEventBuilderManager` to `FairRoot::Base`. |

The other optional libraries depend on packages that CMake finds or does not find. All options are
on the page [CMake reference](/reference/cmake/).

## The libraries

For each library, "Public dependencies" lists the `PUBLIC` or `INTERFACE` entries of
`target_link_libraries()`. A target that links the library gets these dependencies too.
Libraries with a ROOT dictionary also get `ROOT::RIO` as a public dependency, see
[ROOT dictionaries](#root-dictionaries).

### FairRoot::MCStepLogger

A logger for the steps of the transport engine. You do not link it. You load it into a simulation
with `LD_PRELOAD`. It has its own versions of `Stepping()`, `FinishEvent()` and `FinishRun()` of
`FairMCApplication`. They log the data and then call the original functions in `libBase`
([MCStepInterceptor.cxx](/source/fairroot/mcsteplogger/MCStepInterceptor.cxx/#L52-L79)).

- The library has no header files and no ROOT dictionary.
- It has no public dependencies. It links `FairRoot::Base`, ROOT, VMC and the system library for
  dynamic loading as private dependencies.

See [Log the MC steps](/tools/step-logger/).

### FairRoot::FairMQ

A header-only wrapper of [FairMQ](https://fairrootgroup.github.io/FairMQ/). Its interface
dependency is `FairMQ::FairMQ`.

- `FairMQ.h` includes the main FairMQ headers. For FairMQ versions before 1.4.41, it also defines
  the new names in the namespace `fair::mq`, for example `fair::mq::Device`. It has the function
  `fairroot::GetFairMQDeviceChannels()`.
- `FairRunFairMQDevice.h` is for the main file of a device program. You implement
  `fairGetDevice()`, and the header defines the function `getDevice()` that FairMQ calls.

<Snippet file="fairroot/fairmq/FairRunFairMQDevice.h" start="// FairRoot API during transition period" end="std::unique_ptr<fair::mq::Device> fairGetDevice" />

`FairRunFairMQDevice.h` defines functions that are not `inline`. Include it in only one source
file of a program.

## ROOT dictionaries

These libraries have a ROOT dictionary: `Tools`, `Alignment`, `GeoBase`, `ParBase`, `Base`,
`Generators`, `TrackBase`, `Geane`, `FastSim`, `MCConfigurator`, `EventDisplay`, `Online` and
`DataMatch`. The CMake function `fairroot_target_root_dictionary()` makes the dictionary with
`rootcling`
([FairRootTargetRootDictionary.cmake](/repo/cmake/modules/FairRootTargetRootDictionary.cmake#L135-L153)).

For each of these libraries, the build installs two more files into the library directory:

- `lib<name>.rootmap`, the rootmap file. ROOT uses it to load the library when a macro uses one
  of its classes.
- `G__<name>_rdict.pcm`, the PCM file that ROOT reads together with the dictionary.

`<name>` is the output name of the library. For `FairRoot::Generators`, the files are
`libGen.rootmap` and `G__Gen_rdict.pcm`. The function also adds `ROOT::RIO` as a public
dependency, if it is not a public dependency of the library already
([FairRootTargetRootDictionary.cmake](/repo/cmake/modules/FairRootTargetRootDictionary.cmake#L159-L181)).

## Include the headers

Each library installs its headers with `install(FILES ... DESTINATION ${CMAKE_INSTALL_INCLUDEDIR})`.
This command drops the subdirectories: `fairroot/base/steer/FairRunSim.h` becomes
`include/FairRunSim.h`. Thus include a FairRoot header with its file name only:

```cpp
#include "FairRunSim.h"
#include "FairRootManager.h"
#include "FairVersion.h"
```

The targets give the right include directory to your code:

- In the build tree of FairRoot, each target has its source directories as
  `BUILD_INTERFACE` include directories, for example `fairroot/base/steer` and
  `fairroot/base/sim` for `FairRoot::Base`.
- After the installation, each target has `include` as its `INSTALL_INTERFACE` include directory.

The `LOG()` macro is in the header `<fairlogger/Logger.h>` of the FairLogger package.
`FairLogger.h` includes it.

The build installs a header only if the CMake list of the library names the header or its source
file. Thus some headers in the source tree are not installed:

| Header | Why it is not installed |
| --- | --- |
| `FairAnaSelector.h`, `FairRunAnaProof.h` | Only with `BUILD_PROOF_SUPPORT` |
| `FairEventBuilder.h`, `FairEventBuilderManager.h` | Only with `BUILD_EVENT_BUILDER` |
| `FairLmdSource.h`, `FairMbsSource.h`, `FairMbsStreamSource.h`, `FairRemoteSource.h`, `MRevBuffer.h` | Only with `BUILD_MBS` |
| `FairDoubleHit.h`, `FairWriteoutBufferAbsBasis.h` | No CMake list has them |
| `ptrevcomm.h`, `ptrevmbsdef.h` | Internal headers of the MBS sources in `Online` |

The API reference also lists the classes of the headers in this table.

## Link the libraries in CMake

The installation has a CMake package. Each target in it has the namespace `FairRoot::`
([FairRootPackage.cmake](/repo/cmake/private/FairRootPackage.cmake#L22-L27)). Add the
installation prefix of FairRoot to `CMAKE_PREFIX_PATH`, so that CMake finds the package. The
package does not find the packages that FairRoot depends on, so find them too. Then link the
targets that your code uses:

```cmake
find_package(FairRoot 19.0 REQUIRED)
find_package(ROOT REQUIRED)
find_package(FairLogger REQUIRED)

add_library(MyDetector SHARED MyDetector.cxx)
target_link_libraries(MyDetector PUBLIC FairRoot::Base FairRoot::GeoBase FairRoot::ParBase)
```

The project template links the same three targets for its detector
([NewDetector/CMakeLists.txt](/repo/templates/project_root_containers/NewDetector/CMakeLists.txt#L41-L48)).
It finds FairRoot in another way: through the environment variable `FAIRROOTPATH` and
`FindFairRoot.cmake`, and it finds the dependencies with `find_package2()` of FairCMakeModules
([templates/project_root_containers/CMakeLists.txt](/repo/templates/project_root_containers/CMakeLists.txt#L19-L39)).
[Use FairRoot in a CMake project](/start/cmake/) explains both ways and shows a complete project.
[The CMake package](/reference/cmake/#the-cmake-package) lists the variables that the package sets.

Keep these points in mind:

- The targets need the imported targets of their dependencies, for example `ROOT::Core`,
  `FairLogger::FairLogger` and `ROOT::VMC`. If FairRoot uses the separate VMC package, the VMC
  target is `VMCLibrary`, and you must find `VMC` too.
- Each exported target has the interface compile feature `cxx_std_<N>`, with the C++ standard of
  the FairRoot build. Thus your target compiles with at least this standard
  ([FairRootTargets.cmake](/repo/cmake/private/FairRootTargets.cmake#L11-L28)).
- The libraries of the examples, for example `ExMCStack` with `FairStack`, are installed with
  `BUILD_EXAMPLES`, but they are not in the CMake package
  ([examples/common/mcstack/CMakeLists.txt](/repo/examples/common/mcstack/CMakeLists.txt#L52-L53)).
  The names `FairRoot::ExMCStack` and `FairRoot::ExPassive` exist only in the build tree of
  FairRoot.
