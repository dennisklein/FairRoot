What does each layer of the simulation stack cost?

This report follows one experiment. We take the full source of a real simulation (ALICE O2 FV0 with Geant4 through VMC), build it from source with only CMake and GCC, and measure the cost of each layer. Then we remove the layers one at a time. Each step must keep the physics equal.

Result so far

The organizational layers are cheap. Two implementation choices are expensive.

23.3 msper event (± 0.16), fixed cost 1.9 s

49.6 %TGeo navigation (ROOT)

The time per event comes from 5 seeds × 1000 events on one core: (wall time − fixed cost) / 999. The fixed cost is the median of three 1-event runs: 0.6 s start-up and 1.3 s for the Geant4 physics tables at the first event.

Geant4 navigates in the ROOT geometry (TGeo) through g4root, because O2 uses TGeo as the geometry source. The navigation costs half of all instructions per event. The O2 Chebyshev field map costs one quarter. Geant4 physics and stepping cost one eighth. The VMC interface and the FairRoot dispatch layer cost almost nothing for FV0.

T1a removes the 1.9 M libm fmaf calls per event in the field map: the compiler now emits the FMA instruction inline. The field map drops from 24.5 % to 20.1 % of the instructions. TGeo navigation is now 58 % of all instructions. The bit hash changes, because FMA rounds differently, but the gate shows that the physics is equal.

T1b removes 3 % of the instructions, but it is 5.5 % slower than T1a (about 2 standard errors). LTO works only inside one shared library. Calls between functions of the same library still go through the PLT when the function is exported, because the dynamic linker may replace an exported function at run time (symbol interposition). The PLT calls inside Geant4 drop only from 316 k to 254 k per event, and inside ROOT from 242 k to 206 k. The library boundary, not the compiler, limits LTO here. T2 removes this boundary.

T2a lets the compiler and the linker bind calls inside one library directly. The PLT calls inside Geant4 drop from 254 k to 93 k per event, and inside ROOT from 206 k to 34 k. T2a is 4.6 % faster than T1b, but only as fast as T1a. So LTO in shared libraries gains nothing here, also when interposition is off. The fixed cost drops from 1.80 s to 1.53 s, because the dynamic linker resolves fewer symbols.

T2a has one side effect. At start-up, ROOT reads a TObject after delete, to see if delete changes the memory (CheckingDeleteSideEffects in TObject.cxx). Reading freed memory is undefined behaviour. Without interposition, the compiler optimizes this probe, and ROOT prints an error and turns off its deleted-object detection. The physics is not affected, but ROOT depends on code that a compiler may legally break.

T2b: static link with whole-program LTO

T2b links Geant4, VMC, geant4_vmc and all O2 libraries statically into fv0sim, with LTO over the whole program. ROOT stays shared, because Cling and the I/O need its libraries. A second interleaved series measured it with the earlier builds. The machine was slower in this session, so the absolute numbers are higher; only the ratios count.

T2b is 1.6 % faster than T2a, which is within the noise. The calls between the layers now go direct: no PLT call remains between Geant4, geant4_vmc and O2. But these calls were few, about 0.2 M per event. The cost per event stays in TGeo navigation (56 %) and in the field map (24 %), and both are inside one layer.

Two practical findings. ROOT looks for the dictionary file (_rdict.pcm) of a dictionary next to the program, not in lib/, when the dictionary is linked statically. And the linker drops dictionaries that nothing references, so the archives must be linked whole.

Inside a layer, calls between its own shared libraries also go through the PLT: 310,000 per event inside Geant4 and 244,000 inside ROOT. A static link with LTO (T1, T2) removes them.

Method

How the branch is built

  • Every dependency is imported as source into extern/, one commit per package, with the upstream URL, tag and commit in the message. Versions follow the ALICE production stack (alidist): ROOT v6-36-10-alice4, Geant4 v11.2.0-alice4, geant4_vmc v6-6-update4-p5, VMC v2-2, Pythia 8.318, O2 daily-20261112.
  • From O2 we import only the closure that FV0 needs: 145 source files and about 347 headers. A link-map closure finds the sources, and an include closure with both GCC and Clang finds the headers. O2 already carries the FairRoot simulation core (Detectors/3rdparty/FairRootBase), so a separate FairRoot is not necessary.
  • One CMake superbuild builds everything. It requires CMake and GCC only. CMake downloads the Geant4 physics data into a cache outside the build tree.
  • fv0sim is a reduced copy of o2-sim-serial. One cut keeps the CCDB out of the link: the field comes from the nominal setting.
Physics gate

Each transformation must keep the physics equal

The gate compares a candidate build with the reference build on independent seeds. Event observables use the two-sample KS test. Hit observables use permutation tests over whole events, because hits in one event are correlated. The gate passes when every p-value is above 0.01 divided by the number of tests (Bonferroni). An equal hit hash is a diagnostic only.

The first gate tested hits as independent samples. It failed for two seed sets of the same build (cell χ² = 246 for 39 degrees of freedom). With event permutations, the same data give p = 0.40. We also added the hit offset from the straight line of its track. This observable shows the bending in the field.
